## 修复内容

原实现是常驻watcher，用脚本路径比较去重；状态可能停在watching或attempt in progress，不能证明引擎仍活着。它缺少原子互斥、当前请求关联和可靠终态。不能据此断言此前中断的唯一原因；迁移时实测未发现仍运行的目标旧引擎。

现在由现有调用入口按需执行一次：

- 启动器使用设备现有flock，实际并发启动已验证在输入前拒绝；输入脚本另持Java FileChannel锁，进程结束时由系统释放。
- 每次有独立请求标识和有效期，只读取匹配本次请求的结果，旧status不能冒充当前成功。修复设备shell毫秒乘法溢出，改用秒字符串拼接生成毫秒时间，已在设备验证。
- 核对目标页面、本人匹配标记、屏幕及尺寸，先持久化尝试标记再输入。仅一次输入，不在循环中重试；异常、中断或结果未知保留保护。
- 离开手势页后，还须在已知应用页面稳定一段时间才解除本次标记。返回page_left只证明此层结果；调用方仍保留应用就绪检查，不把Activity变化当业务成功。
- 不再常驻监听手动打开APP；自动化运行仍通过原入口自动输入。现有无障碍服务只检查已绑定，不新增权限或改网络/SSH；临时启动组件恢复原默认状态。

## 自动触发候选与冲突策略

设备未暴露窗口事件注册API，采用现有AutoX服务下的单实例页面检测；Java锁与心跳共同判定实例状态，不用旧watching文字替代活性。检测层只触发本人匹配的手势页，调用原有一次性输入核心。同一页面episode不重复触发，短暂启动覆盖层不重新武装，稳定离开页面后才允许下次登录。

输入层为自动检测和显式入口共享：重叠时败方不输入、不覆盖全局结果；显式调用等待进行中的输入或复用刚成功的结果。存在未知输入保护时不自动清除。仅复用既有认证开机入口启动检测，不改业务调度、凭据或权限。开机入口修改不等于重启已验收。

本机已验证episode去重、共享worker的重叠/晚到、入口4种等待或失败路径；私有适配包含本人标记，不公开。通用episode gate可运行：

```sh
node tools/pixel-auth/test-trigger.cjs
```

真实安装和自动冷启动/再次重开/显式调用重叠结果以当前执行报告为准，候选不是验收通过。
