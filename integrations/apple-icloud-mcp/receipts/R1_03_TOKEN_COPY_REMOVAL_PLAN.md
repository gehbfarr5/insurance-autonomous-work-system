# R1-03 旧凭据副本清理方案（待授权，未执行）

- **状态**：**仅方案**。本文档描述的任何动作都未发生；执行需要焦点人明确批准。
- **来源**：R1-03 执行回执（`R1_03_BOUND_ID_PROBE_RESULT.json` v2）§preexisting_residue 发现的残留。
- **性质**：清理对象不是本轮产物，且它同时是"R1 收尾声明不成立"的证据。批准即接受删除该证据，本文档与回执是它删除前的公开记录。

---

## 1. 对象（唯一）

一个 harness 目录，**仅此一个**：

| 属性 | 值 |
| :--- | :--- |
| 创建时间 | 2026-11-10 21:23（本地），早于 R1 真实窗口 |
| 名称形态 | `r1-harness-<UTC时间戳>`，位于 MAC-1 工程用户家目录下（完整路径只在私有运行日志，公开文档不给） |
| 内容 | `r1_bridge_client.py`、`r1_gate.sh`、`r1_watchdog.sh`、`r1_window.sh`、`token`（0600，65 字节） |
| 凭据状态 | token 与**当前在用**的桥令牌逐字节一致（核对方法：对文件做 sha256 后与本轮提取的令牌比对；摘要值不进公开文档） |

**明确不在对象内**：在用配置文件（令牌的权威所在）、LaunchAgent plist、桥服务本身、两棵证据树、家目录下任何其他文件。清理是单路径操作，不做通配。

## 2. 保留的脱敏证据

删除前记录、删除后公开保留的只有这些（完整路径与完整哈希进私有运行日志）：

- 文件名、字节数、mtime（上表已列，执行时按实复核一遍）；
- "token 与在用凭据一致"的结论及核对方法（不含摘要值）；
- 四个脚本在仓库 pinned 版本的哈希（§7.4.1 已有，删除不损失任何独有内容）。

**不做归档**：把目录复制到别处等于再造一份活凭据副本，与清理目的相反。回退靠下面的补偿控制，不靠留副本。

## 3. 执行步骤（批准后按序）

1. **只读复核对象未变**：目录存在、五个文件的名字/字节数/mtime 与发现时一致。若目录变了（多了文件、mtime 不同）→ **停止并重新报告**，不删。
2. **记录清单**：逐文件 sha256 写入私有运行日志（公开层只有上表）。
3. **删除该目录**：单路径 `rm -rf`，不使用通配符，不触碰其他任何路径。
4. **删除后核验**（见 §4）。
5. **回执**：在私有运行日志追加一行"removed at <UTC>，manifest 一致"，公开层在结果回执的 `preexisting_residue` 加 `"removed": true` 与时间。

## 4. 清理后如何复核

范围**只限四项**：目标目录、常驻服务、闸门、权威配置。不做家目录浅层扫描或其他外延搜索。

| # | 核对项 | 通过标准 |
| :--- | :--- | :--- |
| 1 | 目标目录 | 不存在 |
| 2 | 常驻服务 | 进程数 1、pid 与清理前相同、`/health` 200、`store=production` |
| 3 | 闸门 | plist 键仍 `false`，plist sha256 前缀与清理前一致 |
| 4 | 权威配置 | 在用配置文件未被触碰（mtime 与 sha256 前缀不变） |

全部只读；任何一项不符即停止并报告，不做修复性动作。

## 5. 回退

- 删除不可逆（有意不留副本）。补偿控制：
  - 四个脚本在仓库 pinned 版本可随时重建（哈希在申请 §7.4.1）；
  - 令牌可由权威配置经 `r1_token_extract.sh` 重新导出（该工具是仓库受控脚本）；
  - 目录里没有任何独有内容。
- 若批准后希望"先看清单再删"，可在步骤 2 后暂停——清单落盘后再删，顺序不变。

## 6. 边界

- 对象若在发现与执行之间发生变化 → 停止重报（§3.1）。
- 若复核发现该 token **不再**与在用凭据一致 → 停止：它可能是更早的另一把凭据，属于另一个决定。
- 本方案不改配置、不重载服务、不触碰 Apple 数据、不涉及 Seoul、不影响 R2 状态。
