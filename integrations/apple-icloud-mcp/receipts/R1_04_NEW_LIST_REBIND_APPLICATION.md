| 判定 | 断言 |

## 1. 测试列表与合成事项

### 1.1 唯一测试列表名

**`MUSE-R1-04-SYNTEST`**（逐字符，ASCII，无空格）。

- 选名理由：与既有列表（B2 记录的掩码名 `M****试`）无碰撞风险；在元数据读取里可做**精确相等**匹配；后续任何回执里出现这个名字即指向本列表。
- 同名即停：发现步骤若出现同名、或 ≥2 个候选，见 §3.4 停止规则。

### 1.2 目标 iCloud 账户确认方法（三重核对）

| 层 | 方法 | 不符时 |
| :--- | :--- | :--- |
| 用户侧 | 创建列表时确认它建在「提醒事项」侧栏的 **iCloud 分组**下（不是"我的 Mac 本地"） | 建错分组 → 列表不会出现在 calDAV/iCloud 元数据里 → 发现步骤 0 候选 → UNKNOWN 停止 |
| 元数据层 | 匹配条目的 `sourceType == "calDAV"` 且 `sourceName == "iCloud"` | 不符 → 停止改绑 |
| 账户层 | 匹配条目的 `sourceID` 必须等于**旧绑定里的 sourceID**（当前 plist `EVENTKIT_BRIDGE_BINDINGS` 第 2 段，执行时在服务器上读取，只进私有记录）。`EKSource.sourceIdentifier` 是账户级稳定标识，相等 = 同一账户 | 不符 → **账户不符 → 停止改绑**（绑定保持旧值不动） |

## 3. 新列表 ID 与来源绑定的取得

### 3.1 既有可验证来源：核查结论 = 无

公开回执里旧列表标识全部掩码；私有日志无旧 ID 存档；旧 ID 已 404 不适用；**新列表尚不存在，其 ID 任何既有来源都不可能有**。结论：只能走一次账户级列表元数据读取。

### 3.2 明确申请的账户级元数据读取（范围与字段）

- **端点**：`GET http://127.0.0.1:18765/reminders/lists`（Bearer 认证）。这是账户级端点——本方案唯一一次把它用作**数据来源**。
- **响应字段**（源码逐行核对：`RemindersList.swift:38-61`，`EventKitBridgeServer.swift:397-404`）：每个列表返回 `listID`、`title`、`sourceID`、`sourceType`、`sourceName`、`color`、`isImmutable`。**不含任何事项内容与计数**（`FIX-R4A-01`）。
- **只在受控窗口内读**（W0）：看门狗武装（期限 300 s / 预算 120 s）→ `r1_gate.sh open`（legacy 模式，因此时绑定仍指旧 ID，probe 模式无法验证）→ `r1_list_discover.py` 1 次 → `r1_probe_close.sh`（legacy 模式）关闸并验证。

### 3.3 匹配规则

按序判定，全部基于 200 响应的候选数组：

1. `title == "MUSE-R1-04-SYNTEST"` 精确相等的条目为候选；
2. 候选数 = 1 → 检查 `sourceType=="calDAV"` 且 `sourceName=="iCloud"` → 再检查 `sourceID == 旧绑定 sourceID`；
3. 全部通过 → 该条目的 `listID`+`sourceID` 写入服务器 0600 私有文件，供改绑与窗口参数使用。

### 3.4 停止规则（命中即不改绑）

| 情形 | 处置 |
| :--- | :--- |
| 0 候选（列表没建、或建错账户、或未同步） | **UNKNOWN**：只读核对一次（核对私有记录与用户侧确认），**禁止重发第二次枚举**；记录后等人工 |
| ≥2 个同名候选 | 停止改绑；不做任何选择；等人工消歧 |
| `sourceType`/`sourceName` 不符 | 停止改绑 |
| `sourceID` ≠ 旧绑定 sourceID（账户不符） | 停止改绑；绑定保持旧值；列表保留待处置 |

### 3.5 丢弃措施

响应中除唯一匹配条目外的**一切内容**（其他列表的 ID、标题、来源、颜色）不落盘、不进回执、不进日志；匹配条目只保留 §3.3 第 3 步所列字段；`color`、`isImmutable` 不记录。完整标识只存在于服务器 0600 私有文件与私有运行日志，验收结束随 harness 一并删除。

## 4. 改绑与回退

### 4.1 成对变更

| 键 | 旧值 | 新值 |
| :--- | :--- | :--- |
| `EVENTKIT_BRIDGE_ALLOWED_LIST_IDS` | 旧列表 ID（掩码 `9D9A****03F3`） | 新列表 ID |
| `EVENTKIT_BRIDGE_BINDINGS` | `旧ID:旧sourceID:calDAV:iCloud` | `新ID:新sourceID:calDAV:iCloud` |

两键同时、一次改绑完成，不出现"白名单已换、绑定未换"的中间态。权威来源按既有 plist 优先规则判定（R1-03 实测 `gate_source=launchd_env`）；`r1_rebind.sh` 在两键于 plist 与 config 同时存在时拒绝执行。

### 4.2 验证

改绑后（闸门仍关）：`/health` 200 + `store=production`；进程身份（pid 变更记录）；静态检查（allowlist 恰为新 ID、binding 为 calDAV/iCloud、gate=false）；带令牌行为探测 403 `PERMISSION_DENIED`。**"绑定真的可用"由 W1 的 200/`[]` 证明**，改绑步骤本身不声称这一点。

### 4.3 回退

- 改绑任一步失败 → `r1_rebind.sh` 自动恢复备份（两键回旧值）→ 同一入口重载 → 重验服务健康与 403。
- W1 得 `RESOLVED_SOURCE_IDENTITY_CHANGED`（来源身份与绑定不符）→ 停止 → 恢复备份 → 重载 → 验证。新列表保留。
- 最终核验：plist 与改绑前备份逐字节比对，**除两键外必须一致**；不一致即报失败。
- 旧绑定完整值记入私有日志与改绑回执（掩码进公开层），任何时候可精确还原。
