## 2. P1 最重要的已确认事实（不得混同为 S1 选择）

- **A 客户经营：** 公司活动与主管客户名单是主要触发；首次接触大多为孤儿单客户，经历邀约前筛查和见面后筛查；平台会后再邀约通常较困难。**逐个拨打邀约电话是用户最耗时间与精力的工作**。用户希望将除亲自开展高价值客户关系沟通以外的普通重复事务尽可能托付给 AI。常规基础电话可在未来研究，未获生产授权。
- **B 公司信息：** 主要散落微信群，喜报及不匹配的活动对当下个人目标噪声较大；重要海报通知可能有临时报名截止、名额限制和二维码入口。未来希望 AI 按当前目标筛选消息、办理活动报名、安排日程。**报名可能是用户本人，也可能代客户报名**，取决于活动。已有 Agent 协助处理报名页面的经验。
- **C 内部事务：** 主管安排、培训、考试、报送和系统操作都存在；科技个险培训体系有几乎每日的低价值、规则化、重复互动任务。用户希望 Agent 完全承担，不再日常介入；已有半自动化经验。**该任务业务影响较低，不应因容易自动化而自动成为首选**。
- **D 自主运行：** 既往在科技个险培训及其他操作中，自动化会**查看页面反馈**，不是盲目执行固定脚本；晚宴等公司活动报名另有检查是否成功的 Agent 实践。用户主观评价报名几乎无失误，但未经过正式统计验证。用户要的是**能自主适应页面、核验实际结果、持续改进的 Agent**。
- **长期开放问题：** 客户是否信任、关系是否改善、如何判断关系长期价值，用户与 AI 当前均无成熟可靠标准；需要共同成长，不能在 P2 假装可以已经量化评分。
- **跨领域方向：** 活动通知 → 客户与名额匹配 → 邀约/报名 → 日程与服务 → 核验与复盘。只是潜在闭环，未成为部署和操作权限。
- **总体原则：** AI 主动发现工作、月度提案并与用户确认方向、周度自主组织任务、阶段性复盘；用户主导重要客户关系与现场判断；四维价值为经营结果、减负、客户服务关系、用户成长；优先可靠自主执行与实际减负，不以 Agent 数量作为成果。

## 3. P2 要完成什么

对多个真实场景进行**平行比较**，而不是先选一个再寻找理由：

- **候选 A：** 常规电话邀约及基础客户联系。
- **候选 B：** 公司微信群活动筛选 → 本人/客户报名 → 日程安排与状态确认。
- **候选 C：** 科技个险培训体系每日互动等低价值重复事务。
- **候选 D：** 客户资料整理、首次筛选及后续跟进的组织工作。
- 如有从 P1 证据推导出来的跨领域组合候选，也可单列，但**不要将历史 OCR、LSPosed、自动外呼或任何设备架构视为已选定**。

评估维度至少包括：与业务目标的匹配及实际价值、可释放的用户时间/精力、任务发生频率、完成证据是否容易核验、现存可复用的 Agent 实践、数据与访问前提、对外影响与限制、异常可恢复性、初步实现难度/投入、后续跨领域复用潜力。**不捏造分数、工时、成功率、成本或现有系统权限。** 允许用“已有事实／推测／待验证”及定性比较；若建议分数或权重，须注明是分析工具而非用户已批准标准。

研究需特别分清：
1. 用户“最痛苦、最有业务价值”与“最容易立即验证可靠、实现减负”可能不是同一候选。
2. 可把“高价值长期目标”与“可能的低门槛早期验证工作”分别讨论，不强行二选一。
3. 过去 Agent 半自动化已经成功过的真实经验要保留，但不等于全面系统上线。
4. 不把自动点击、提交动作视为真实业务完成，也不把当前尚未解决的客户关系判断标准化。
5. **P2 是研究和决策，不是 P3 技术设计。** 访问账号、接入方案、外呼授权、技术栈、部署、预算执行等不应先行决定。
