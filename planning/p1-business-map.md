# P1｜四领域真实业务需求地图（已完成，P2 输入基线）

> 状态：2026-10-24，**P1 已于 2026-10-24 经用户最终确认，正式完成；现为 P2 唯一的四领域业务事实输入基线之一**。本文件是进入 P2 的真实业务基线，不是开发规格或 S1 试点优先级。真实客户资料、公司内部原始文件、报名二维码及凭据不进入公开仓库。

## 目标与退出条件

P1 只要求：四个业务域的真实工作目的、主要来源/流程、人工负担或机会、业务结果与核验方式、跨领域依赖及未知事项有足够描述；用户校正关键事实。**不要求在 P1 完成客户关系价值判定方法、精确 KPI、数据接口、具体授权规则或技术方案。** P2 再针对比较中的关键证据缺口做补充调查。

## P1-A｜客户经营：P1 调查完成

**已确认的业务事实**
- 工作主要由**公司活动 + 主管提供的客户名单**共同触发；平台会常用于初次接触，大多数接触对象为此前缺少直接服务关系的“孤儿单客户”。
- 实际上包含**先查看资料并电话邀约、再在见面后筛选后续经营机会**的两轮筛查；现场交流时间有限，会同步了解基本情况及既有保单。
- 首次接触后更常安排下一次平台会，独立拜访较少；二次邀约的成功机会按用户经验偏低，明显购买意向者后续见面更容易。
- 用户还通过保单检视、养客活动、节庆礼品维护关系，付费活动、礼品、时间与精力都构成成本；匿名化的手工活动案例体现后续邀约更顺畅，但不能据此认定已产生转介绍或新单。
- 对于短期没有购买意愿但交流较好的人，用户可能愿意投资于关系与自身职业成长；重要关系和现场判断由用户主导。
- **长期开放能力课题**：人与 AI 目前都没有经过可靠验证的客户关系进展判断方法；不将“客套/主动表达”的临时观察写成评分标准。此项不妨碍 P1 收尾。
- **最新确认的最大工作负担：逐个打电话最耗费时间与精力。** 用户希望把除自己亲自开展的高价值客户接触沟通外的常规工作尽可能交给 AI，释放精力用于重要关系互动。这是委托方向和业务目标，不是当下全面自动化授权，也不表示 S1 已选定外呼。

**P1-A 阶段结论与暂留问题**
- 已具备活动触发、两轮筛查、实际服务方式、投入成本、核心时间负担及人机价值分工的信息，可结束集中访谈；综合地图已由用户整体确认。
- 具体客户记录载体、逐次联络量、历史实际成果及“何为已成功联系”需在 P2 针对被比较候选场景补证，不在 P1 伪造数值或预设工具。
- 关系是否改善由人与 AI 在长期工作中共同探索，**不要求 P1 形成评分与判断规则**。

详细来源：[P1-A 调查记录](p1-a-customer-operations.md)。

## P1-B｜公司信息与经营机会：P1 调查完成

**已确认的业务事实**
- 微信群中公司活动、海报、报名动态、同事业绩喜报、活动总结等信息混杂；人工阅读和筛选费时，临时通知容易被淹没。
- 对用户目前客户结构不匹配的高端客群活动，现阶段实际经营价值较低；其它同事的开单喜报通常不触发本人行动。这种相关性取决于经营目标，不应当作永久关键词黑名单。
- 价值较高的活动通知常带**报名截止、名额、时间和二维码入口**等行动要求，且通知可能很临时。
- 用户已有部分 Agent 协助完成二维码报名页面的经验，希望长期由 AI **筛选信息、报名活动、安排日程**；该期望不等于现已自动化读取微信群或获授权全自动报名。
- **活动报名有两种真实对象：本人报名、代客户报名，依据活动性质决定**；具体字段、责任与流程需要后续按场景细化。

**P1-B 阶段结论与后续问题**
- 已有足够事实确认消息噪声、临时性、海报入口、报名对象与 AI 委托目标，**集中访谈已结束，P1 综合地图已经用户确认**。
- 报名是否成功、名额是否落实、信息来自其它群或渠道的具体范围，属于后续 P2/P3 的针对性核查；此处不制定技术接入及具体授权。
- 本轮截图用于去标识化分析，**不会将原图、群人员/客户资料、二维码及内部消息原文写入公开仓库**。

详见：[P1-B 公司信息调查](p1-b-company-information.md)。

## P1-C｜内部事务与工作组织：P1 调查完成

**已确认的业务事实**
- 用户确认主管临时任务、培训/学习/考试、公司系统操作和数据/资料报送等各类内部事务都存在；公司活动的报名与安排与 P1-B 交叉，日常时间冲突不是主要问题。
- 培训体系还存在**每天要做、类似游戏化签到/互动的低价值重复任务**：用户认为其不是严格必须，但属于日常待完成项目，频率高而繁琐。
- 用户希望**完全放手由 Agent 执行**这些规范化、低价值任务，尽可能不需要本人逐日介入；用户此前已有部分半自动化实践，实际可靠性尚未重新核实。
- **要区分“商业价值低、主观优先级低”与“可以低成本可靠减负”**：这个场景不应仅因流程规则化或自动化倾向就自动成为 S1 试点。

**P1-C 阶段结论与开放问题**
- 当前已具备主要类别、用户负担与委托意图，可结束集中访谈，**综合地图已完成用户复核**。
- 每日任务怎样证明已完成、失败如何交接，以及它与强制培训、真实出勤、考试之间的业务义务区别，仍需在 P1-D 选例研究或 P2/P3 分场景细化。不能推定所有签到和考试都可以代操作。

详细记录：[P1-C 内部事务与工作组织](p1-c-internal-work.md)。

## P1-D｜自主运行与持续改进：P1 调查完成

**已确认的协作原则与真实实践**
- AI 先提出月度经营草案，用户与 AI 共同确认方向；在既定方向和授权内自主组织具体任务、复盘结果，必要时提出策略复评。
- **科技个险中的培训日常任务等操作**：用户以前的自动化实践不是无条件地执行一连串按钮，而是在操作中查看页面反馈以判断状态，已有部分半自动化经验。
- **公司活动报名（例如晚宴）**：与科技个险培训任务是**不同的业务流程**；用户已有让 Agent 辅助操作并检查报名是否成功的经验，主观评价几乎没有失误。
- 用户期待的是**能依据页面与业务反馈调整行动的 Agent**，而非仅有固定指令序列的脚本；项目需要承认已有实践，而不是把结果可核实性误当作从未具备的功能。
- 用户关于 Agent 成功率的描述是**自身实践经验**，不是经过独立抽样验证的零故障结论。未来正式实施的权限、失败恢复、数据条件与验收需按具体场景研究。
- 不同任务的结果判定不同：打卡、报名可观察操作反馈；客户关系价值判断尚不成熟，是用户与 AI 长期共同成长的开放课题，不能提前规范化。

**P1-D 阶段结论与后续问题**
- 已识别具体业务任务、现有页面反馈核验经验与用户对真正自主执行的期待，**可以结束集中访谈**。
- 留待 P2/P3：不同系统/活动的真实验收反馈形式、独立效果样本、外部约束、异常与人工交接、访问权限和实施范围；不把这些技术与授权细节作为当前 P1 收尾的前置条件。

详细来源：[P1-D 自主运行与结果验证](p1-d-autonomy-verification.md)。
