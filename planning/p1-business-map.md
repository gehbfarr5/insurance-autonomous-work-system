# P1｜四领域真实业务需求地图（收尾工作稿）

> 状态：2026-10-24，**P1 正在收尾，尚未通过完成关口**。本文件用于把已知事实和最低限度待补充内容汇总，便于 P2 公平比较不同领域的候选试点；不是开发规格或 S1 优先级决定。用户的真实客户数据、公司内部原始文件和凭据不进入公开仓库。

## 目标与退出条件

P1 只要求：四个业务域的真实工作目的、主要来源/流程、人工负担或机会、业务结果与核验方式、跨领域依赖及未知事项有足够描述；用户校正关键事实。**不要求在 P1 完成客户关系价值判定方法、精确 KPI、数据接口、具体授权规则或技术方案。** P2 再针对比较中的关键证据缺口做补充调查。

## P1-A｜客户经营：核心事实已具备，待综合确认

**已确认的业务事实**
- 工作主要由**公司活动 + 主管提供的客户名单**共同触发；平台会常用于初次接触，大多数接触对象为此前缺少直接服务关系的“孤儿单客户”。
- 实际上包含**先查看资料并电话邀约、再在见面后筛选后续经营机会**的两轮筛查；现场交流时间有限，会同步了解基本情况及既有保单。
- 首次接触后更常安排下一次平台会，独立拜访较少；二次邀约的成功机会按用户经验偏低，明显购买意向者后续见面更容易。
- 用户还通过保单检视、养客活动、节庆礼品维护关系，付费活动、礼品、时间与精力都构成成本；匿名化的手工活动案例体现后续邀约更顺畅，但不能据此认定已产生转介绍或新单。
- 对于短期没有购买意愿但交流较好的人，用户可能愿意投资于关系与自身职业成长；重要关系和现场判断由用户主导。
- **长期开放能力课题**：人与 AI 目前都没有经过可靠验证的客户关系进展判断方法；不将“客套/主动表达”的临时观察写成评分标准。此项不妨碍 P1 收尾。
- **最新确认的最大工作负担：逐个打电话最耗费时间与精力。** 用户希望把除自己亲自开展的高价值客户接触沟通外的常规工作尽可能交给 AI，释放精力用于重要关系互动。这是委托方向和业务目标，不是当下全面自动化授权，也不表示 S1 已选定外呼。

**P1-A 阶段结论与暂留问题**
- 已具备活动触发、两轮筛查、实际服务方式、投入成本、核心时间负担及人机价值分工的信息，可结束集中访谈；综合地图仍待用户校正。
- 具体客户记录载体、逐次联络量、历史实际成果及“何为已成功联系”需在 P2 针对被比较候选场景补证，不在 P1 伪造数值或预设工具。
- 关系是否改善由人与 AI 在长期工作中共同探索，**不要求 P1 形成评分与判断规则**。

详细来源：[P1-A 调查记录](p1-a-customer-operations.md)。

## P1-B｜公司信息与经营机会：已具备阶段性收尾条件

**已确认的业务事实**
- 微信群中公司活动、海报、报名动态、同事业绩喜报、活动总结等信息混杂；人工阅读和筛选费时，临时通知容易被淹没。
- 对用户目前客户结构不匹配的高端客群活动，现阶段实际经营价值较低；其它同事的开单喜报通常不触发本人行动。这种相关性取决于经营目标，不应当作永久关键词黑名单。
- 价值较高的活动通知常带**报名截止、名额、时间和二维码入口**等行动要求，且通知可能很临时。
- 用户已有部分 Agent 协助完成二维码报名页面的经验，希望长期由 AI **筛选信息、报名活动、安排日程**；该期望不等于现已自动化读取微信群或获授权全自动报名。
- **活动报名有两种真实对象：本人报名、代客户报名，依据活动性质决定**；具体字段、责任与流程需要后续按场景细化。

**P1-B 阶段结论与后续问题**
- 已有足够事实确认消息噪声、临时性、海报入口、报名对象与 AI 委托目标，**可以结束集中访谈，待 P1 综合地图由用户复核**。
- 报名是否成功、名额是否落实、信息来自其它群或渠道的具体范围，属于后续 P2/P3 的针对性核查；此处不制定技术接入及具体授权。
- 本轮截图用于去标识化分析，**不会将原图、群人员/客户资料、二维码及内部消息原文写入公开仓库**。

详见：[P1-B 公司信息调查](p1-b-company-information.md)。

## P1-C｜内部事务与工作组织：范围已知，实际调查不足

**已知事实**
- 包括主管指令、培训/学习/考试、签到/报名/资料提交、会议、客户预约和临时工作。日常日历冲突并非主要矛盾。

**待补的最低信息**
- 实际最常发生的任务及其强制性；哪些必须本人到场/判断，哪些只是重复事务；哪些经常占用时间、需要确认完成或容易漏办。

## P1-D｜自主运行与持续改进：长期原则已确认，业务案例待补

**已确认的总体协作原则**
- AI 先提出月度经营计划，人与 AI 共同定方向；方向内可自主组织和调整有授权的任务。AI 可以提出方向复评但不能单方改变重要方向；自主执行必须能核实结果，异常时交接。
- AI 与用户的经营判断力均需要随实际实践逐步提升，不要求现阶段先拥有所有判断标准。

**待补的最低信息**
- 从 A/B/C 选**一两个实际任务**观察“动作已执行”和“业务结果已核实”分别是什么；哪些失败必须让用户接手；哪些工作可用明确事实核验，哪些关系/策略问题当前无法规则化。
- 不在 P1 规定 Agent 架构、工具权限表或生产环境中的重试规则。

## 跨领域工作链条（待核实的候选说明）

公司活动信息 (B) → 用户与主管共同形成任务和名单 (C/A) → 筛选、邀约及现场交流 (A) → 报名/活动安排 (C) → 跟进与服务 (A) → 结果核实和工作方式复盘 (D)。

这是用于调查的逻辑路径，**不能据此声明各步骤都已有授权或已经自动化**。
