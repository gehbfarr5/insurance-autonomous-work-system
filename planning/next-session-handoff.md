## 必须保留的共识

1. 目标是跨客户经营、公司信息、内部事务和自主改进的**整个工作系统**，而非 OCR、自动外呼或日历工具的单点项目。
2. AI 高度自主执行、主动发现机会，但重要客户关系、面对面交流及现场业务判断由用户主导；常规基础电话联系是未来可研究的授权能力。
3. AI 每月**先提出经营计划**，双方讨论确认；AI 可在月度方向内自主增减具体任务，必要时主动要求复评整体策略。
4. 长期评价维度为经营成果、人工减负、客户关系与服务质量、用户本人专业能力成长。先建立可靠执行与减负证据，再扩大经营价值。
5. 个人客户库是日常入口，公司科技个险按需维护；历史纸卡自动化**曾经跑通**，痛点不只是 OCR，也有跨设备中转和实际录入核验。原技术路线不得被认定为新项目必选。
6. 当前**没有决定 S1 的第一业务试点**，不自动以客户信息录入或 AI 打电话作为第一阶段。
7. P1/P2/P3 是规划关口；S1/S2/S3 是候选能力发展层级。两套阶段不可混淆。
8. 公开 GitHub 仓库不得收录客户隐私、公司内部原始资料或凭据。不能宣称任何长期能力已经上线。

## 下一会话合理的推进顺序

1. **先核对最新 GitHub 基线。** 若有新更改，以实际仓库与明确决策为准。
2. **P1：逐业务领域梳理真实工作。** 利用现有记录建立四个领域的简明业务地图；重点询问尚缺的事实，不重复已回答的问题。每次聚焦一个高层业务问题，不进入工具参数或旧自动化细节。
3. **P2：评估 S1 试点候选。** 根据真实痛点、价值、减少人工、可验证性、信息/权限依赖、风险与复用价值，给出有依据的比较和建议，**再由用户决定**。
4. **P3：只有试点获确认后**才讨论具体流程、技术可行性、系统架构、设备职责、权限、成本、验收等。
5. 每达成一项清晰共识，更新相关 GitHub 文档并回读确认；将用户决定与 AI 候选建议明确区分，不将猜测写成“已确认”。
