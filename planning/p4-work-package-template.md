# P4 工作包与验证模板

> 由 P3 准备材料按用途整理。模板不是已填写的方案、授权或已通过的验证；总体框架已确认，任务级内容在 P4 使用时补齐。

## 1. 单个工作包

- 目标、范围及排除项：
- 已确认事实、当前症状、来源和版本环境：
- 当前包真正需要补证的关键条件：
- 输入、来源、必要数据及输出：
- 备选方案、官方/上游依据、许可/维护/兼容性：
- reuse／adapt／avoid 决定及理由：
- 选定路径、实现顺序与资源：
- 允许动作及对应授权；范围外交接：
- 完成判据、证据来源、人工/模拟/自动/生产的区别：
- 异常、停止、恢复与人工接手：
- 实际结果、PASS／FAIL／BLOCKED／INTERRUPTED 及证据：
- 下一步或恢复条件：

不要为了填模板而索取当前包不需要的全部细节。开发、访问、采购、部署、生产执行分别按实际范围明确授权；既有范围内的例行动作无需重批。

## 2. 验证场景清单（计划，未执行）

验证时记录实际观察和证据，不只打勾。测试中模拟的卡顿或错误，只证明对应测试条件下的行为；不能替代真实 APP 证据。故障注入限于获准的测试环境，不在生产中制造重复提交、网络中断或错误数据。

| 场景 | 需观察或构造的条件 | 预期可接受行为 | 不通过表现 |
| --- | --- | --- | --- |
| 正常完成 | 未完成且规则明确的获准任务 | 核对状态、完成允许步骤，再按证据报告 | 只依据点击动作报完成 |
| 开始前已经完成 | 当日/当期有有效完成记录 | 跳过造成重复影响的动作，说明已有结果 | 再次提交或错误归属日期 |
| 提交后卡顿 | 无明确成功或失败反馈 | 将提交结果标为待核实，先查状态 | 连续点击、重放整段流程 |
| 反馈冲突 | 成功提示与任务列表不一致 | 保留冲突，核对有效记录，必要时交接 | 选择更乐观的提示报告成功 |
| 分项部分完成 | 某些步骤有确认结果，其他步骤未完成 | 分项报告，仅处理可安全继续的部分 | 全部重做或整个任务记成功 |
| 身份验证中断 | 登录过期或需要本人验证 | 停止对应动作，交用户正常验证；恢复前重查状态 | 收集密码、绕过验证或直接重放 |
| 页面或任务变化 | 出现未知入口、要求或动作 | 识别变化并暂停对应步骤，保存脱敏摘要 | 根据名称猜测并扩大执行 |
| 任务周期变化 | 跨日、跨月或显示日期不一致 | 明确任务归属和有效期，不使用上期证据 | 用旧记录证明本期完成 |
| 撤回授权 | 用户在运行前或在途操作时要求停止 | 停止新动作，核对在途结果并交接 | 继续排队操作或承诺已撤销不可逆提交 |
| 恢复与接力 | 上次运行中断或用户接手过 | 先读当前实际状态及交接记录，再决定剩余动作 | 假设仍停留原页面、与人工重复操作 |
| 数据边界 | 页面同时出现非必要客户或内部信息 | 只处理必要范围，证据进入获准私密位置 | 将原始信息写到公开仓库或无关存储 |
| 实际减负 | 获准验证期间的真实工作记录 | 对照人工参与、异常接手、维护与核验负担 | 仅用完成次数或演示结果宣称减负 |

实际减负先记录可观察事实：人工何时介入、为什么介入、处理了什么、是否需要重新检查或返工；有真实计时再记耗时，没有计时不补造数字。当前不设置虚构成功率或周期门槛。

## 3. 单任务授权与交接模板（待填，不构成授权）

### 任务范围卡

- 任务名称与类别：待选；类别可扩充。
- 任务目的及公司侧要求：待核实；区分 APP 状态和现实业务事实。
- 来源、触发、周期及期限：待核实。
- 允许动作：逐项明确，区分只读、领取、填入、提交、分享或对外发送。
- 禁止或交接动作：标明本人参与、对外影响、未知声明及权限边界。
- 必要输入及允许来源：仅列必要内容，不包含密码、令牌等凭据。
- 账号、设备与环境：使用非敏感标识；说明登录由谁处理。
- 完成证据与证据局限：待观察验证，不预填为页面成功提示。
- 重试条件与停止条件：先说明如何消除重复风险；无依据不自动重试。
- 授权主体、范围、有效期及撤回方式：待明确；公司侧允许与用户执行委托分开记录。
- 异常负责人、通知方式及恢复条件：待明确。
- 私密记录位置、访问者及保留规则：待明确；公开仓库只保留脱敏摘要。
