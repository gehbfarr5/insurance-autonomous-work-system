### 二、P3 首项工作目标

先调查**重做后的新系统**中每日互动任务的业务流程和实施条件，形成可供用户审阅的方案准备材料。具体包括：

1. 任务由什么业务事件或时间触发、目标结果是什么、有哪些必要输入。
2. 当前新系统中任务实际如何完成；允许通过实际反馈逐步厘清，**不要要求用户一开始就给出界面级完整指示**。
3. 如何区分“已尝试操作”“页面显示完成”“结果已实际确认”；哪些结果证据可靠。
4. 常见失败、超时、重复提交、部分完成、页面状态不明确等情况如何识别、记录和交接。
5. 哪些步骤可由 Agent 独立处理，哪些情况需要用户或公司规则确认；明确委托意愿不自动等于账号权限、公司授权或生产操作批准。
6. 新系统所需的数据、账号/环境、系统权限及公司规则有哪些，先核查事实，不预设已获访问权。
7. 根据业务流程再比较可能的方案、验证顺序、回滚/停止方式与资源需求；不继承旧项目技术栈，不假设旧代码可用。
8. 给出业务结果验证方向和 P3 阶段的“继续/暂停/调整”判断条件。不捏造工时、费用、成功率、周期或量化门槛。

### 三、阶段与授权边界

- P3 是规划关口；S1 是未来系统能力阶段。两者不能混淆。
- 当前 P3 工作限于业务流程调查、事实核查、风险与权限梳理、方案比较和实施准备。
- **不要直接开发、部署、自动操作公司系统、提交任务、批量处理客户、自动外呼或修改生产数据。**
- 用户明确希望每日互动最终可完全交由 Agent；这记录为业务委托意愿。实际执行仍需核查新系统流程、公司规则、权限和结果证据。
- 与 C 相关的其他任务仍是完整试点范围，但这轮不自动扩展调查或实施对象。
