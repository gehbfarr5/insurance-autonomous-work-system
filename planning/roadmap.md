# 分阶段规划与决策关口路线图 v0.1

> **定位：一份可执行的规划路线图，而非未经验证的开发排期。** 2026-10-24 达成了项目愿景、业务版图、协作方式与长期评价原则的共识；**用户已选择 C（科技个险培训体系每日互动任务）作为 S1 首个试点；试点边界、技术实现和具体时间表仍待细化**。

## 0. 避免两套“阶段”混淆

- **P：项目规划与需求细化工作**。决定先研究什么、收集什么事实、形成何种方案；旧 [Issue #1](https://github.com/gehbfarr5/insurance-autonomous-work-system/issues/1) 曾使用 “Phase 2” 表达下一步业务需求梳理，仅指这类规划工作。
- **S：系统自主能力的发展阶段（候选）**。表示未来要验证的能力层级，不等于 P 的同名阶段，也不意味着已经开始建设。

## 2. 候选能力发展路线（S）——尚未定稿

### S1：可靠自主执行与重复劳动减负

目标：在经过讨论确定的**一个或少数真实工作场景**中，证明 AI 有能力在授权范围内可靠工作，而不仅仅给出计划或演示。

可能需要验证的能力：任务来源清楚、结果可核实、失败可交接、用户不需反复手工中转、确有减负。**试点领域待选；不默认客户资料、电话或任何特定渠道优先。**

### S2：跨业务协调与工作方式优化

目标：在已有可靠基础上，协调客户经营、公司信息和内部任务中的相关工作；进一步减少数据重复、人工交接和上下文丢失。

可能的结果：某项活动信息能触发合适的客户经营工作、后续跟进与管理任务，且具备可追溯的业务结果。具体系统集成与运行模型待选。

### S3：共同经营判断与持续自主进化

目标：以月度规划、周度组织、主动策略复评与实际成效学习为持续工作方式；AI 能提出新的经营机会、改善流程，用户本人也不断提高业务判断力。

可能的结果：实际经营成果、服务质量及个人能力获得可观察的改善。**不以 Agent 数量、自动任务数或推理能力宣传作为交付成果。**

S1/S2/S3 只是**候选能力阶段**：顺序、并行范围、阶段数量、正式名称、交付时间与验收阈值均可依据 P1/P2 结果调整。

## 3. 每个阶段都应遵守的共同工作模板

逐阶段细化时，至少形成以下项目内容（**此处为模板，不是已填好的答案**）：

1. **业务目标与范围：** 要解决什么真实问题，做与不做什么。
2. **现状证据：** 用户确认的事实、样本、过去失败或成功经验、尚缺信息。
3. **预期改善：** 选择四维成效中的相关方向，如何观察变化。
4. **人机分工与授权：** 哪些可自主执行，哪些必须由人确认或亲自完成。
5. **候选流程和跨领域依赖：** 工作从何而来，怎样确认结果。
6. **风险、例外与外部约束：** 公司规定、客户承诺、数据处理权限、出错后的交接和回滚。
7. **验收与退出判断：** 成功证据、不合格情形、进入下一范围的前提。
8. **尚未决定的事项：** 保持待定，不让假设混入确认清单。

## 4. 阶段优先级应如何产生

建议比较候选场景的**真实工作痛点、潜在减负、可验证性、风险、信息依赖、实现成本和未来复用价值**，再由用户结合现场经验决策。用户已选择科技个险每日低价值重复任务（C）作为 S1 首个试点；这是具体试点决定，实施细节仍待进一步规划。
