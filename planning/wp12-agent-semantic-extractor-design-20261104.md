# WP12：Agent (MUSE) LLM 语义结构化提取架构升级方案 (2026-11-04)

## 一、背景与问题根因

在 WP11-S 真实卡片实测中发现：
1. **多行地址截断：** 客户手写常住地址跨为两行时，原 `fields.py` 死板正则只匹配首行，导致第二行门牌/村组丢失。
2. **性别字段缺失：** 卡面“男/女”选框和打勾（√）符号未被有效提取绑定。
3. **主客户姓名大面积被置空：** 当卡面下方存在多位家属（配偶、子女）时，硬编码规则因害怕混淆触发 `MAIN_CUSTOMER_IDENTITY_UNCLEAR` 将姓名置空。
4. **根因归结：** 错把应当由 LLM 语义中枢（Agent / MUSE）处理的“上下文自然语言理解、跨行实体缝合与主次区分”塞给了死板的 Python 正则与局部几何规则。

参考历史成熟项目（MacServer `/Volumes/DTC810/migrated-home/desktop/科技个险/kjgx-handwriting-eval`）的成功架构，决定将语义结构化解析中枢正式确立并交付给处理流程 Agent（MUSE）。

## 三、Agent 语义解析契约规范

### 1. 结构化目标 Schema
```json
{
  "name": "主客户姓名（严格排除家属）",
  "gender": "男 / 女",
  "mobile": "11位手机号码",
  "identity_number": "18位有效身份证号",
  "birthday": "卡面手写出生日期（如：1964年08月22日）",
  "address": "完整多行拼接地址（如：河南省信阳市平桥区前进乡光明村1组21号）",
  "review_status": "PENDING_USER_CONFIRMATION"
}
```

### 2. 核心语义规则
- 仅提取主客户（投保人），家属信息一律不提取；
- 严禁擅自从身份证号无中生有推导出卡面未填写的生日；卡面明确手写的生日优先提取；
- 地址栏如有折行，自动根据语义拼接为完整地址，不保留无意义标签前缀。
