# P1-D｜自主运行、结果验证与持续改进（业务调查中）

> 初稿：2026-10-24。围绕已经调查的实际工作，而非抽象 Agent 架构或技术选型。此文件只形成事实来源与开放问题；不宣称任何任务已获生产自主执行许可。

## 1. 已确认的总体方向（既有 D-001—D-019，不重新决策）

- AI 在事先确认的方向和权限内主动发现并完成常规任务，不能停留在建议、演示或“操作看起来执行了”。
- 月度经营方向由 AI 建议并与用户共同确认；周度具体工作在既定方向内自主组织。重大经营方向变更需与用户讨论。
- AI 须区分已尝试、已执行与**真实结果已经核实**；异常与超出边界的事项需要交还给用户。
- 用户希望将高价值直接客户交流之外的大量重复事项尽可能委托 AI，自己集中于客户关系；客户关系判断及双方业务能力成长属于**长期开放能力课题**，不能提前定评分规则。

## 2. 从 P1-A/B/C 抽出的两类业务案例

### 案例 A：培训体系每日互动任务（P1-C）

**真实事实**：几乎每日出现、业务价值低、繁琐而比较规范化；用户曾半自动化处理，希望未来完全委托 Agent，日常不介入。

**尚待确认**：界面上的何种反馈意味着当天真实完成？例如任务状态、积分/进度或明确成功反馈——这些只是示例，**不是经用户确认的既有界面或完成标准**。未完成、页面变化、登录失效等情况对工作的实际后果是什么？这些判断属于 P1-D/P2 的业务证据，不在此给出自动重试规则。

### 案例 B：公司活动发现、本人/客户报名（P1-B）

**真实事实**：来自分散的微信信息、海报及报名页面；有临时截止；报名主体因活动而异；用户有时让 Agent 协助报名。

**尚待确认**：表单提交与报名确实被接受、名额确认、活动安排落实之间如何区分；什么变化会需要用户处理？实际核验方式尚未从用户处获得。

## 3. 可用的 P1-D 初步业务结论（只提出区分）

- **做了动作**不必然等于**完成业务任务**；用户要求的是结果可信且能减轻人工检查负担。
- 日常规范化工作与具有复杂外部结果的报名，其完成证据与失败后果可能不同；不应使用统一的未经验证标准。
- 可由 AI 自行完成和改进的具体权限、成功率、操作方式及失败处理需在业务候选确定后进一步明确。
- 与用户共同成长的经营判断能力不可与“完成一次明确任务”混为一类；不能虚构对关系改善的自动评价能力。

## 4. 最小剩余调查与 P1 收尾

- 优先让用户就一个熟悉任务说明：**现实中凭什么认定今天已经完成，而不是只点击了按钮？** 最好有直接可见、无需敏感数据的结果反馈。
- 不要求为每类事务在 P1 都给出完整验收规则；能识别结果与动作的区别、知道重要未知项在哪，即可由用户复核综合地图并进入 P2。
- **P2/S1 尚未选择任何领域或场景**。具体授权、接入、日志、错误恢复、重试、验证方式留待 P2/P3 按需细化。
