## 2. 四类候选的平行比较

| 候选场景 | 业务价值与减负 | 频率与实践基础 | 自主执行与结果核验 | 依赖、风险与复用 |
| --- | --- | --- | --- | --- |
| **A. 常规电话邀约与基础联系** | **事实：**逐个拨打是用户目前最耗时间和精力的工作；活动和主管名单会触发客户联系。**判断：**与主要痛点和客户经营结果联系最直接。 | 由名单与活动触发；实际频率和拨打量未统计。 | 自主拨号不等于有效沟通；还需识别是否接通、是否传达、后续是否需要跟进。 | 依赖客户资料、外联边界与公司要求；错误联系可能影响客户体验。潜在复用高，进入前需清楚授权、结果证据和人工接管条件。 |

这里的 A/B/C/D 是候选编号，不能与四个业务领域直接混用。例如候选 D 是资料组织，而业务领域 D 是自主运行与改进。

## 3. 试点取舍

### C：已确认作为 S1 首个试点

用户于 2026-10-24 明确选择 C 作为 S1 首个试点，并补充确认 C 的业务范围包括每日互动任务、培训课程、题目答题相关的日常、特定活动、客户筛选内容报送、每月收入计划等公司要求完成的细碎工作。C 因此是一个内部日常工作域，覆盖操作型与内容型事务。

该选择确认 C 作为业务域及 S1 的能力目标，不表示新系统已具备执行能力。用户明确表示每日互动任务可完全委托 Agent，并确认优先把它带入 P3 做流程调查；这只是调查顺序，不是生产执行批准。其他类别纳入 C 总范围，其自主边界和实际执行顺序需逐类细化。建议保留完整范围并按任务类型分批评估。旧项目的半自动化程序仅为历史参考，不能证明新系统可复用、可运行或可通过正式发布验证。新系统的页面反馈、异常表现和证据形式需在 P3 与后续实际反馈中核查、迭代。

### A：价值最高的长期减负目标之一

A 对应用户明确指出的最大时间精力负担，并且直接联系客户经营。它应保持在候选前列，但自主外联比 C 带来更多对外影响和结果判断要求。可在后续比较是否先从准备与组织等边界较清楚的工作切入，之后再评估自主联系范围；此处不预设实施顺序或授权。

### B：可核验业务闭环的备选

B 有现存 Agent 报名经验与可检查结果，可作为 C 的替代 S1 候选。可比较明确活动通知到报名确认的有限闭环；全群消息筛选、客户匹配、代客户报名和日程协同不默认一次性纳入。

### D：潜在共享基础能力

D 可能为 A、B 提供客户资料和跟进组织能力，但资料权限、现有记录方式和减负规模尚不清楚。当前将它列为候选基础能力，不预设独立成为 S1 或先于其他场景实施。

## 4. C 的任务结构与分批方向

### 4.1 任务类型及差异

用户确认下列工作都纳入 C。以下分类是为了比较任务结构，不表示各类工作已获相同程度的自主执行确认，也不代表它们必须同一批次上线。

| 工作类型 | 用户列举的事项 | 主要结果形态 | P2 需要关注的差异 |
| --- | --- | --- | --- |
| **日常互动操作** | 每日互动任务 | 在公司系统完成日常任务，并根据页面反馈确认状态 | 旧项目有半自动化与页面反馈实践，仅作历史参考；新系统结果证据尚未验证。 |
| **课程与答题** | 培训课程、题目答题相关日常 | 完成课程/答题流程，可能同时产生学习或测验结果 | 需区分页面显示完成、实际答题内容和任务规则；具体流程尚未核实。 |
| **特定活动** | 公司要求参与或完成的特定活动 | 按活动要求完成相应事项并确认结果 | 活动类型、时间要求、是否需要提交内容或参与记录尚不清楚。 |

| **月度收入计划** | 每月制定当月收入计划等 | 形成并按要求提交月度计划 | 可能涉及目标判断、经营输入及内容质量；需识别哪些步骤可以由 Agent 自主准备，哪些需要用户给出方向或校准。 |

**分析判断：** C 的完整业务域已由用户确认，S1 的目标是在该域内逐步让 Agent 承接繁琐公司要求工作，减少用户日常参与，并建立结果核验与异常交接能力。建议保留 C 完整范围，按任务类型分批评估。每日互动可作为候选起点，因为它高频、重复且用户已明确委托；旧程序不能作为新系统可靠性证据。课程/答题、特定活动、客户筛选报送及收入计划分别涉及学习/答题内容、活动规则、客户数据与提交、经营输入与计划判断，需先梳理业务级边界，再于 P3 核查流程与所需证据。

## 5. 结果与能力路线

### 5.1 成功结果方向

- **C：** 高层方向是 Agent 承接 C 范围内公司要求完成的繁琐工作，并依据适合各任务的证据确认结果。用户已确认优先将每日互动带入 P3 调查；旧项目曾基于页面反馈判断每日任务状态，但这是历史参考；新系统的页面反馈及结果证据尚未验证；课程、答题、活动、客户筛选报送和收入计划等的结果证据可能不同，具体状态与异常规则在实际操作中结合页面反馈和用户意见逐步校准，当前不要求预先给出界面级指示。
- **B：** 区分信息已识别、报名已提交、报名已确认和日程已安排；不得把提交动作当作报名成功。
- **A：** 区分拨号、有效联系、邀约和后续结果；不把拨出电话等同于完成沟通。
- **D：** 核对资料整理和跟进事项是否准确完整；不以自动关系评分作为成功指标。

具体基线、周期、目标值和门槛尚未设定，需依据选定候选补充，不在本阶段虚构数字。

### 5.2 候选能力阶段关系

- **S1 已确认试点业务域：** C（公司要求完成的细碎重复内部事务，含科技个险的互动、培训、答题、活动、客户筛选内容报送及月度收入计划等）。C 内部的具体任务分批顺序仍待确定。B 保留为有可核验报名实践的后续候选；A 是更直接对应客户经营与主要人工负担的高价值候选；D 是可能支持 A/B 的共享基础能力。
- **S2 候选方向：** 在已有可靠执行能力上连接活动信息、客户资料、邀约、日程与后续任务，具体依赖待 P2/P3 再定。
- **S3 候选方向：** 共同开展经营复盘、策略建议和持续改进。客户关系判断须在实际工作中长期学习，不以当前不存在的评分标准作为前置条件。

P 阶段是规划关口，S 阶段是候选能力路线；两者不可混淆。
