# 《家庭卡 OCR 与人工复核审核员操作规范 (v1.0-Candidate)》

## 一、系统定位与安全原则

本系统用于太平洋保险《家庭卡 OCR → iCloud 联系人》的结构化提取与建档。为杜绝客户隐私泄露与通讯录污染，系统遵循以下铁律：
1. **零推导原则：** 严禁从身份证号码推导出生日期，仅当卡面有明确填写的生日时才记录。
2. **纯粹原则：** 仅提取主客户（投保人）信息，家庭成员、保单金额、险种详情等严禁写入联系人。
3. **闭门确认原则 (Fail-Closed)：** 当版面、字迹或字段存在任何歧义时，系统强制触发 `REVIEW_REQUIRED`，必须由人工审核员逐字段复核并显式确认后，才允许向通讯录发起单次单条创建。
4. **防误覆盖原则：** 默认情况下，严禁覆盖或删除已有联系人。

## 二、审核员工作流程

### 步骤 1：获取待审核草稿
当 OCR 解析完成且系统触发人工复核时，系统会在受保护安全目录（权限为 `0600`，仅当前操作员可读写）生成待审核草稿 JSON：
- 文件路径示例：`/protected/path/<card_id>_draft.json`
- 初始状态：
  ```json
  {
    "extraction_status": "MANUALLY_REVIEWED",
    "review_status": "PENDING_USER_CONFIRMATION",
    "name": "",
    "mobile": "",
    "identity_number": "...",
    "review_reasons": ["table_layout_uncertain", "mobile_uncertain", ...]
  }
  ```

### 步骤 2：逐字段复核与修改
审核员比对家庭卡原始纸质卡片或受保护影像，对草稿中各个字段进行核对与补全：
1. **姓名 (name)：** 核对是否为主客户（投保人）姓名，去除无关称谓。若字迹潦草，需向经办人或投保单核实。
2. **手机号 (mobile)：** 校验是否为 11 位有效手机号码（以 1 开头）。
3. **身份证号 (identity_number)：** 核对 18 位身份证号码与校验位，严禁录入非主客户的身份证。
4. **生日 (birthday)：** 仅当卡面有明确填写的出生日期时录入（格式：`YYYY-MM-DD`），若未填写则保持为空。
5. **地址 (address)：** 核对为主客户家庭常住地址，忽略工作单位地址。

### 步骤 3：显式确认 (User Confirmation)
审核员在确认所有字段准确无误后，将草稿文件中的审核状态修改为确认状态：
```json
"review_status": "USER_CONFIRMED"
```
> **警告：** 若 `review_status` 不为 `"USER_CONFIRMED"`，任何下游建档程序都会直接报错拒绝执行（`RuntimeContractError`）。

### 步骤 4：执行单次建档与回读核验
审核员调用写入入口（通过受保护 CLI）：
```bash
python3 wp10_create_readback.py --confirmed-draft /protected/path/<card_id>_draft.json
```
系统将自动执行：
1. **查重校验：** 比对 iCloud 联系人库，若存在相同手机号或姓名，拒绝重复创建。
2. **单次创建：** 仅写入主客户姓名、手机号、明确生日、地址及规范备注。
3. **实时回读：** 写入后立即向 iCloud CardDAV 发起读取校验，确保写入数据与草稿 100% 一致。
4. **归档与清理：** 成功后自动清理本地敏感草稿，记录操作流水日志（流水日志不包含明文敏感信息）。

## 三、常见复核原因与处理指引

| 复核原因代码 | 常见原因 | 审核员操作规范 |
| :--- | :--- | :--- |
| `table_layout_uncertain` | 卡面表格倾斜、折痕或拍照角度偏差导致列边界模糊 | 手动根据原始卡片表格线，确认各单元格与字段的对应关系 |
| `main_customer_identity_unclear` | “投保人”或姓名手写连笔，单字识别置信度不足 | 比对原件字迹，确认真实姓名后填入草稿 |
| `mobile_missing` / `mobile_uncertain` | 客户未留手机号、字迹潦草或填写了固定电话 | 若有手写手机号则手工录入；若确实未留，按业务要求向客户补录或终止建档 |
| `address_conflict` | 卡面上同时存在“家庭地址”与“工作单位” | 仅保留常住家庭地址，清空单位地址 |
| `identity_number_uncertain` | 身份证末尾为 'X' 识别不确定或字迹辨识度低 | 核对原件 18 位号码并手工修正 |

## 四、安全与合规审计

1. 审核员不得将任何包含客户真实姓名、身份证、电话的草稿文件、图片或截图复制到非受控目录、公开代码仓库或公共即时通讯软件中。
2. 审核终端离开人员视线时必须锁屏。
3. 发现身份证号校验位错误或明显伪造卡片时，应报告合规主管并标记废弃。
