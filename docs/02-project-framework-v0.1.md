# 项目总体框架 v0.1

**状态：暂定规划框架。** 用于整理已识别领域与概念，不构成完整需求规格，也未选择 Agent 框架或技术实现。

## 自主进化闭环（暂定）

`Scout → Architect → Builder → Verifier → Reporter`

| 角色 | 初步职责 |
| --- | --- |
| **Scout** | 发现工作、问题、异常与改进机会。 |
| **Architect** | 分析目标与约束，设计或重新设计方案。 |
| **Builder** | 在授权范围内实施改进或完成任务。 |
| **Verifier** | 独立检查结果，并按验收规则判断是否达成。 |
| **Reporter** | 记录执行情况、证据、经验和后续建议。 |

这是职责划分的概念模型，不表示将以五个独立 Agent、特定框架或固定顺序实现。

## 系统级主动经营闭环（长期目标，非技术方案）

**已确认的长期定位：** AI 应主动经营整个工作体系，持续发现机会、评估价值、统筹并执行授权范围内的工作、检验业务结果，并持续改进甚至重新设计工作方式，而非只被动完成已知任务。

初步从两个相互关联的视角理解：

- **业务经营闭环（概念）：** 感知工作信息与业务变化 → 发现任务／机会 → 评估价值并决定优先顺序 → 跨领域组织执行 → 验证业务结果与跟进。
- **工作方式进化闭环（概念）：** 从任务成效、失败和新机会发现流程问题 → 重新设计工作方式 → 在授权与验收规则内改进 → 验证并沉淀经验。

这两条闭环共同作用于整个工作体系；下面的 Scout → Architect → Builder → Verifier → Reporter 是可能的职责视角，**不要求固定五个独立 Agent，也不预定运行技术**。人的角色不仅是定义目标、维护重要关系和参与关键判断，**也可以与 AI 共同探索尚不清晰的目标及业务策略**；不要求人先给出全部答案。

## 人与 AI 共同成长的经营关系（已确认的方向）

用户不要求自己先明确所有获客策略、客户经营方法或工作价值标准，再交给 AI 执行；也不希望这些长期职业判断完全由 AI 替代。系统应同时支持两种互补关系：

- **自主执行层：** AI 按既定规则积极发现、评估、组织并完成日常业务工作。
- **共同判断层：** 面对未明确的业务目标、获客策略、客户关系经营和长期职业发展，人和 AI 共同提出问题、对比假设、结合经验与结果修订判断。

**候选的共同学习循环：** 观察业务现状 → 共同形成问题与假设 → 选择可检验的尝试 → 回顾实际效果 → 更新双方对业务价值的认识。它是协作方式的概念，**不是新增某个技术 Agent 或预设具体 KPI**。

系统的价值不仅体现在自动化完成多少工作，也包括用户本人对业务的理解、独立判断与职业能力能否随合作逐渐提升；衡量方式尚未确定。

## 情境化人机分工与沟通边界（已确认方向）

系统保持高度自主，但不意味着 AI 取代人对客户关系、职场情境与重要业务判断的主导权。用户以「至少约 60% 的判断由本人做」表达对重要判断的主导倾向，并非严格的数字配额。

- **真人主导：** 面对面交流、需要本人直接参与的重要客户沟通、职场情境判断、关系维护；AI 应重视用户掌握的现场信息，接受纠正，也可提出有依据的不同意见。
- **AI 可自主：** 常规电话联系（例如基础邀约、通知）、日常安排、技术性判断以及明确授权的事务；实际行动以相应业务边界和授权为前提。
- **共同判断：** 获客方向、长期经营策略、工作价值标准及职业发展，在真实业务经验中共同探索并修正。

**框架定位已澄清：** 「AI 可以承担常规电话联系」与「重要的直接客户交流和面对面关系维护由真人完成」可以同时成立。具体场景规则与外呼技术后续再谈。

## 周期性整体经营规划（已确认方向）

用户反馈日常工作通常没有明显的时间冲突；因此日程冲突管理不是主要价值点。AI 可以主动评估非强制活动，但更应以**月度和周度**统筹业务方向和后续行动。公司活动本身通常按月安排。

- **月度视角（协作方式已确认）：** AI 先综合公司活动、客户经营机会及其他工作依据，主动提出月度经营计划草案；人和 AI 共同讨论、补充现场信息、调整并确认经营方向。
- **周度视角：** 把月度方向转化为近期值得执行的行动，跟踪结果并动态修正。**已确认：** AI 可在确定的月度方向及既有授权内，自主增加、取消或调整具体工作；如需改变整体经营重点，先与用户共同讨论。对公司明确要求和已作出的客户承诺，不因任务调整权而自动获得取消权。
- **日常视角：** 自主处理授权事务和临时变化，不把消解日常时间冲突视为核心目标。

上述月、周、日是**概念层的节奏建议**，具体报告形式、频率、判断标准尚未定稿；不得视为已创建自动化。

## 已识别的业务领域

以下为初步业务范围，具体任务边界、来源、优先级、频率和授权方式待讨论。

### 客户经营

- 多来源客户资料整理
- 客户资料批量录入
- 客户分类筛选
- 活动邀约与跟进
- 客户联系记录和后续关系维护

### 公司信息管理

- 公司活动信息的主动发现、整理及后续业务机会识别（微信群是已知的主要通知渠道；接入方式待研究）
- 产品信息与更新
- 业务公告和重要信息整理

### 公司内部事务与日常工作协调

已确认纳入长期业务范围：

- 微信群通知、主管安排与临时工作任务
- 公司培训、学习、考试及相关事务
- 签到、报名、资料填写与提交等行政事项
- 会议、活动、客户预约和个人工作日程
- 其他内部事务，允许持续补充

这一领域不仅负责单项任务，也要与客户经营和公司信息管理共同协调工作。具体权限与实现尚待讨论。工作指标和业绩进度目前未确认是否纳入。

### 系统运行与改进

- 任务调度
- 异常处理
- 运行记录
- 结果核验
- 自主优化与版本管理

### 跨领域场景：公司活动主动经营（候选业务闭环）

公司活动不是仅供阅读的一条通知，而可能触发客户筛选、邀约、报名、执行和后续经营。当前已确认该方向应纳入总体框架，暂以「活动信息感知 → 活动要求理解 → 客户适配分析 → 联系与执行安排 → 结果回顾」描述候选闭环。

该场景由公司信息管理、客户经营、内部事务和自主运行机制共同支持；微信群是现实中的主要活动通知来源，但获取方式及实际执行能力尚未确定。具体技术留待后续阶段。
