# 开放问题与后续决策关口

> **状态：仅列当前尚未解决的事项。** 已确认的原则见 [决策日志](03-confirmed-decisions.md)，不在此重复要求用户作答。总体框架已经整理完成，但没有确定 S1 具体业务试点。

## P1 已关闭｜保留的业务事实缺口（不是 P1 未完成）

**P1 四领域调查已于 2026-10-24 经用户确认完成。** [P1 综合业务需求地图](../planning/p1-business-map.md) 为正式输入基线。下列是研究深入时仍可能需要证据的方面，**不要求重新进行 P1 全面访谈**：

- **客户经营：** 逐个电话邀约是最大时间精力负担；联系成功率/频率、具体客户记录与交接方式、是否能稳定减负，应在 P2 比较候选时定向核实。客户关系改善与主观判断属于长期共同成长，不强行规定评分。
- **公司信息：** 活动通知混在微信消息和海报中，有时临时且需要报名；本人及客户报名均存在，部分 Agent 报名已有良好经验。群消息可用性、不同活动的真实成功反馈及时效要求应按候选核对。
- **内部事务：** 科技个险中的每日游戏化互动等任务规则化、重复且价值较低，已有半自动化；规范是否允许代操作、长期真实减负及失败影响留待后续。
- **自主运行：** 用户有根据页面反馈判断操作是否完成的经验；精确错误率、独立结果验证、异常交接和对外权限仍需针对具体选定任务明确。

以上是 **P2/P3 的按需补证事项**，不是 P1 的未完成项目，也不表示相关能力已获授权或生产上线。

## P2：试点与阶段边界（尚未决定）

- S1 究竟从哪个或哪些业务切入？是否与用户过去首先提到的客户资料和打电话一致，仍须综合价值、负担、可验证性和约束比较后决定。
- 是否保留 S1/S2/S3 三个候选阶段、是否允许能力交叉建设、哪些前置依赖不可跳过？
- 如何定义从“试点有效”到“值得扩大自主范围”的证据？具体阶段指标、成本、资源与时间安排是什么？
- 哪类任务优先减负、哪些经营机会优先研究，正式顺序待共同确定。

## P3：选定业务范围后细化

- **授权与对外沟通：** 每类自动联系的适用场景、合法与公司制度约束、升级人工的条件、撤回与停止方式；什么样的客户关系动作必须由人执行？
- **信息与记录：** 数据来源允许的用途、敏感信息保护、个人客户库与公司系统写入边界、去重与一致性原则、权限与数据生命周期。
- **执行与验证：** 结果证据、失败重试、不可确认状态、人工接力、业务承诺的处理和工作流变化的回退标准。
- **技术与资源：** 哪些既有代码、设备、模型或云资源有复用价值；是重新设计还是修复；只有在业务要求清楚后才选择。

## 工作成果如何衡量（具体指标待定）

长期四个维度已确认：经营成果、人工减负、客户关系和服务质量、用户个人成长。**尚未确认**每一维度的指标、权重、采集方法、基线和评估周期；不应编造目标数字。

## 已解决、请勿反复询问的共识

- **人机分工：** 常规基础电话可作为 AI 授权目标，重要关系及面对面交流由真人主导；用户掌握的一手事实要被尊重。
- **经营规划：** AI 先提出月度计划，双方确认方向；月度方向内可自主调整任务；可随时主动提出方向复评，但不单方面决定战略变更。
- **长期方向：** AI 主动发现机会、跨领域统筹、可靠执行并持续改进；先可靠减负，再扩大经营价值。
- **现实侧重点：** 用户日常几乎没有严重排程冲突，项目不应围绕日历冲突处理定义主要价值。
- **架构原则：** 历史技术栈只作参考，不必沿用，未选定具体 Agent 数量、模型或设备职责。
